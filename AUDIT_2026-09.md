# Spreadsheet / Grid32 Audit — Round 2

Audit performed 2026-09-20 against `c550b61`. Round 1 (`GRID32_AUDIT.md`) covered
Grid32 memory safety and is fully closed; this round covers **correctness,
the MFC host wiring, scale, and feature gaps** across both projects.

Each item carries a checkbox; commits referencing a fix should tick the box.
Severity key: **B** = blocker (silently wrong results or data loss), **H** = high
(a feature the user can reach that does not work), **M** = medium (robustness /
API), **P** = performance & scale, **E** = enhancement.

---

## Blockers — silent wrong answers or data loss

- [ ] **B1** `SUM`/`AVERAGE`/`MIN`/`MAX`/`COUNT` over a range return **only the first
  cell** (`Formulator.cpp:185-287, 374-412`). `ParseCellRef` (`Formulator.cpp:167`)
  parses `"A1:B10"` as a *valid single reference*: the alpha scan stops at `A`,
  then `std::stoul(L"1:B10")` returns `1` without throwing, so the function
  reports success with `row=0, col=0`. Every range helper tests
  `if (!ParseCellRef(arg, sr, sc))` first and therefore never reaches its
  colon-splitting branch. `=SUM(A1:A100)` silently evaluates to `A1`.
  Fix: make `ParseCellRef` reject trailing junk (require the whole token to be
  consumed), and add a dedicated `ParseRange`.

- [ ] **B2** Editing a cell never recalculates dependent formulas.
  `SetCellText` (`Grid32Mgr.cpp:1320-1384`) is the normal typing path
  (`GM_SETCELLTEXT` → `grid32_wndproc.cpp:262`, and the edit-control commit at
  `EditWndProc.cpp:18`) and it is the **only** mutator that does not call
  `RecalculateFormulas()` — `SetCell`, `ClearCellText`, `DeleteCell` all do.
  Type `5` into A1 and `=A1*2` in B1 keeps its stale result until some other
  edit happens to trigger a recalc.

- [ ] **B3** The formula `visited` set is never unwound, so a value referenced
  twice evaluates as `0` the second time. `GetCellValue`
  (`Formulator.cpp:705-723`) inserts into `visited` for cycle detection but
  never erases on the way out, and `visited` is shared across the whole
  evaluation. `=A1+A1` returns `A1`, not `2*A1`; `=SUM(...)+A1` drops the `A1`.
  Fix: make it a *path* set (erase on scope exit, RAII guard) rather than a
  global visited set, or memoize per-cell results.

- [ ] **B4** The document is never marked dirty and never marked clean.
  `SetModifiedFlag` is called nowhere in `Spreadsheet/`, and
  `CSpreadsheetDoc::OnSaveDocument` (`SpreadsheetDoc.cpp:131`) overrides the
  base without calling `CDocument::OnSaveDocument`, which is what normally
  clears the flag. Result: **closing the app after editing never prompts to
  save** — edits are lost without warning.

- [ ] **B5** Undo/redo of a formula cell destroys the formula.
  `OnUndo` (`Grid32Mgr.cpp:2749`) and `OnRedo` (`Grid32Mgr.cpp:2824`) restore
  `EditOperationType::SetText` via `SetCellText(..., op.oldState.m_wsText)` —
  the *display text*. A cell holding `=B1+1` that displays `5` comes back as the
  literal text `5`. `oldState.m_wsFormula` / `m_bFormula` are captured in the
  undo record but never used.

- [ ] **B6** Paste corrupts every row's last cell. `OnPaste`
  (`Grid32Mgr.cpp:2697-2719`) splits with `std::getline(rows, line)` on `\n`,
  but `CF_UNICODETEXT` uses CRLF, so the trailing `\r` stays on the last
  tab-separated field of each line. `InferType` then fails on `"42\r"` and the
  value lands as text, breaking sorting and formulas.

- [ ] **B7** CSV stream-out performs no quoting or escaping
  (`Grid32Mgr.cpp:3842-3858`). A cell containing `,`, `"` or a newline produces
  a corrupt file. Round 1 added RFC 4180 quote *parsing* on stream-in (H7);
  the writer was never updated, so CSV does not round-trip.

## High — reachable features that do not work

- [ ] **H1** Cut / Copy / Paste show a message box and do nothing.
  `CSpreadsheetView::OnEditCut/OnEditCopy/OnEditPaste`
  (`SpreadsheetView.cpp:152-168`) are generated `// TODO` stubs whose entire
  body is `MessageBox(L"Cut", ...)`. They are bound to `ID_EDIT_CUT/COPY/PASTE`
  in `CSpreadsheetView`'s message map (`SpreadsheetView.cpp:43-45`) and so
  **shadow the working implementations** in `CGridView::OnEditCut/Copy/Paste`
  (`GridView.cpp:121-137`), which correctly forward `WM_CUT`/`WM_COPY`/`WM_PASTE`
  to the grid. Delete the stubs and let the base handlers run.

- [ ] **H2** `CSpreadsheetView::OnEditSelectAll` (`SpreadsheetView.cpp:172`) and
  `OnCellFont` (`:191`) are empty stubs bound to their command IDs — same
  shadowing problem as H1.

- [ ] **H3** Undo, Redo, Clear, Find and Replace are unreachable from the UI.
  `CGridView` declares `OnEditUndo`, `OnEditRepeat`, `OnEditClear`,
  `OnEditFind`, `OnEditReplace` (`GridView.h:39-43`, implemented at
  `GridView.cpp:145-171`) but neither `CGridView`'s message map
  (`GridView.cpp:23-31`) nor `CSpreadsheetView`'s maps `ID_EDIT_UNDO`,
  `ID_EDIT_REDO`, `ID_EDIT_CLEAR`, `ID_EDIT_FIND` or `ID_EDIT_REPLACE`.
  The grid implements all of them; nothing routes the commands.

- [ ] **H4** Select All does nothing even when reached. `CGridView::OnEditSelectAll`
  (`GridView.cpp:141`) sends `end = {(UINT)-1, (UINT)-1}`, and `OnSetSelection`
  (`Grid32Mgr.cpp:2896-2901`) *rejects* `end >= gcs.nHeight/nWidth` with
  `GRID_ERROR_INVALID_CELL_REFERENCE` instead of clamping.

- [ ] **H5** Replace All can loop forever. `CGridView::OnReplaceAll`
  (`GridView.cpp:96-115`) loops on `ReplaceText` and restarts each search at
  the cell just replaced. `OnReplaceText` (`Grid32Mgr.cpp:3707`) replaces only
  the first occurrence in that cell, so replacing `a` with `ab` re-matches the
  same cell indefinitely. The search start must advance past the replacement.

- [ ] **H6** Formulas have no comparison operators. `ParseExpression` /
  `ParseTerm` / `ParseFactor` (`Formulator.cpp:289-703`) handle only
  `+ - * /` and parentheses. `IF(A1>5,1,0)` parses `A1`, then stops at `>`,
  so the condition is *the value of A1* and the rest of the argument is
  discarded — `IF`/`IFS`/`AND`/`OR` silently produce wrong answers. Need
  `> < >= <= = <>` (and ideally `^` and `&`).

- [ ] **H7** Bold/italic over a multi-cell selection flattens per-cell fonts.
  `MutateCurrentFont` (`MainFrm.cpp:394-402`) reads the **current cell's**
  `FONTINFO`, mutates one field, and hands the whole struct to
  `SetSelectionFormat`, which assigns `cell->fontInfo = fi` for every cell in
  the range (`Grid32Mgr.cpp:1160`). Selecting an Arial-12-red cell and a
  Times-20-blue cell and clicking **B** makes both Arial 12 red bold.
  Formatting needs per-attribute merge, not whole-struct replace.

- [ ] **H8** Number formats do not apply to formula cells.
  `SetCellNumberFormat` (`Grid32Mgr.cpp:1185`) guards with
  `if (pCell->m_eType != CT_Text && !pCell->m_bFormula)`, so applying Currency
  to a `=SUM(...)` cell changes nothing on screen.

- [ ] **H9** Alignment and wrap changes are not undoable.
  `SetSelectionHAlign` / `VAlign` / `Wrap` (`Grid32Mgr.cpp:1244-1284`) mutate
  `justification` directly and never build a `GridEditOperation`.

- [ ] **H10** Merged cells are dead code. `mergeRange` is in the model,
  serialized by SSF (`Grid32Mgr.cpp:3921`, read back at `:4262`), and
  `IsCellMerged` / `DrawMergedCell` / `SelectMergedRange`
  (`Grid32Mgr.cpp:798-866`) exist — but **nothing calls them**: `DrawCells`
  does not consult them, and there is no message to set a merge range.
  `CMainFrame::OnAlignCmd`'s `ID_ALIGN_MERGE` case is an empty comment
  (`MainFrm.cpp:702-705`).

- [ ] **H11** Cell background colour is a no-op. `OnFontBackground`
  (`MainFrm.cpp:478-486`) parks the colour on `m_cellBkg` because there is no
  `GM_SETBACKGROUND`; the Highlight ribbon button does nothing.
  `cell_base::clrBackground` exists and `DrawCells` already honours it.

- [ ] **H12** Print and Print Preview produce a blank page. `CGridView::OnDraw`
  (`GridView.cpp:36`) and `CSpreadsheetView::OnDraw` (`SpreadsheetView.cpp:74`)
  are empty — the grid is a child HWND that paints itself on screen and is not
  part of the view's printing DC. Needs a real `OnPrint` that renders cells to
  the printer DC with pagination.

- [ ] **H13** Escape does not cancel a cell edit. `EditCtrl_WndProc`
  (`EditWndProc.cpp:32-72`) handles Return/arrows but not `VK_ESCAPE`, so there
  is no way to abandon an in-progress edit; clicking away commits it via
  `WM_KILLFOCUS`.

- [ ] **H14** Pressing **F1** (and other virtual keys) opens the cell editor.
  `OnKeyDown`'s `default:` branch (`Grid32Mgr.cpp:1966-2005`) treats the
  *virtual key code* as a character: `iswalnum(VK_F1 /* 0x70 */)` is
  `iswalnum(L'p')` → true. The grid has no `WM_CHAR` handler at all, so the
  printable character is inferred from VK codes — which also breaks IME,
  dead keys and non-ASCII layouts. Editing should start on `WM_CHAR`.

- [ ] **H15** `OnStreamIn` never clears existing content
  (`Grid32Mgr.cpp:4008`), and there is no message to clear the grid —
  `DeleteAllCells` (`Grid32Mgr.cpp:1450`) is not reachable from outside.
  `CSpreadsheetDoc::OnOpenDocument` (`SpreadsheetDoc.cpp:89`) therefore *merges*
  the opened file into whatever the SDI document already held.

- [ ] **H16** `OnFilterCells` does not filter (`Grid32Mgr.cpp:3594-3638`). It
  collects matching rows and then sets the selection to
  `matchedRows.front() .. matchedRows.back()` — a contiguous rectangle that
  includes every non-matching row in between. There is no row-visibility flag
  in `ROWINFO` and no paint-time support, so filtering is unimplemented.

- [ ] **H17** Several `CGridCtrl` wrappers always return `FALSE`.
  `StreamIn`, `StreamOut`, `SetCurrentCellFormat`, `SetSelectionFormat`,
  `SetRangeFormat` (`GridCtrl.cpp:57-73, 152-160`) return
  `SendMessage(...) != 0`, but the matching wndproc cases `break` and fall
  through to `DefWindowProc`, which returns 0 for these `WM_USER+n` messages
  (`grid32_wndproc.cpp:240-260, 380-388`). Callers must inspect
  `stream.m_dwError` instead; the API is misleading.

- [ ] **H18** `GM_ENUMCELLS` discards `OnEnumCells`'s return value
  (`grid32_wndproc.cpp:375-378`) — the caller cannot learn how many cells were
  copied, or query the count with a null array.

- [ ] **H19** ODF export emits `<text:p>` without declaring the `text:`
  namespace (`Grid32Mgr.cpp:3934-3946`) — the output is not well-formed XML
  and no ODF reader will accept it.

- [ ] **H20** `SF_TEXT` and `SF_RTF` are declared (`grid32.h:37-38`) but handled
  by no branch of `OnStreamOut`; the request silently succeeds and writes an
  empty string. `SF_XLSX` (`Grid32Mgr.cpp:3954`) emits a bare SpreadsheetML
  fragment, not a ZIP container — Excel cannot open it.

- [ ] **H21** `ParseCellRef` accepts malformed references and can produce
  `UINT_MAX` row indices: `"A0"` yields `row = 0 - 1 = 4294967295`
  (`Formulator.cpp:176`), `"A1B"` is accepted as `A1`, and the `col` accumulator
  has no overflow or grid-bounds check.

- [ ] **H22** `Grid32_WndProc` pops a `MessageBox` when `pMgr` is null
  (`grid32_wndproc.cpp:20-25`). Any message arriving before `WM_NCCREATE`
  re-enters the message pump from inside a window procedure. It should return
  `DefWindowProc` quietly.

## Medium — robustness and API

- [ ] **M1** `SetCell` leaves a dangling pointer in `mapCells` on allocation
  failure (`Grid32Mgr.cpp:1024-1034`): it does `delete it->second;` and then
  `it->second = new GRIDCELL(gc);`, returning from the `catch` with the freed
  pointer still in the map. Allocate into a temporary first, then swap.

- [ ] **M2** Row/column indices are packed into 16 bits by
  `MakeGridPointFromWPARAM` and `MAKELRESULT`
  (`grid32_wndproc.cpp:8-14, 291-298`), capping every message-based API at
  65535 rows/columns regardless of `gcs.nHeight`.

- [ ] **M3** Inconsistent packing order: `GM_SETCURRENTCELL` reads
  `row = LOWORD, col = HIWORD` (`grid32_wndproc.cpp:291-292`) while every other
  message uses `col = LOWORD, row = HIWORD` (`:11-12`). `GridCtrl.cpp:129`
  carries a comment warning about it — the convention should be unified.

- [ ] **M4** STL types cross the DLL boundary. `grid32.h` puts `std::wstring`
  in `FONTINFO`, `cell_base` and `GRIDCELL`, and `GCFILLSTRUCT`/`GCFINDSTRUCT`/
  `GCREPLACESTRUCT` pass `std::wstring` by value through `SendMessage`. Host and
  DLL must be built with an identical toolset, CRT and `_ITERATOR_DEBUG_LEVEL`
  or the heap mismatches. `GCFILLSTRUCT` also carries a **reference member**
  with a default initializer (`grid32.h`, `std::wstring& m_wsText = refGC.m_wsText;`),
  which makes the struct non-assignable and is not a POD layout.

- [ ] **M5** `OnRedo` (`Grid32Mgr.cpp:2810`) has no `try`/`catch`, unlike
  `OnUndo` — the round-1 L4 fix was applied only to undo, so a throw mid-redo
  still leaves a half-restored grid.

- [ ] **M6** Spurious undo entries: `OnReplaceText` (`Grid32Mgr.cpp:3723`) and
  `SetCellNumberFormat` (`:1172`) call `GetCellOrCreate(..., true)`, which
  records a `SetFullCell` op *in addition* to the operation's own record —
  two undo steps for one user action.

- [ ] **M7** `OnClear` (`Grid32Mgr.cpp:2558-2575`) and `OnCut` (`:2658-2662`)
  loop over the selection calling `DeleteCell` / `ClearCellText`, each of which
  runs a full `RecalculateFormulas()`. `m_bDeferRecalc` exists for exactly this
  and is used by paste and sort but not here.

- [ ] **M8** `SetCellFormat` calls `RecalculateFormulas()` on a font change
  (`Grid32Mgr.cpp:1124`) — formatting cannot affect formula results.

- [ ] **M9** `OnGetCellText` returns `TRUE` while setting
  `GRID_ERROR_NOT_EXIST` for a missing cell (`Grid32Mgr.cpp:3170-3172`) —
  success and error at once.

- [ ] **M10** `OnCopy` writes only `m_wsText` (`Grid32Mgr.cpp:2594`), so copying
  a formula cell yields its rendered result and copying a currency cell yields
  `$1,234.00` as text. Copy should carry formulas and a private clipboard
  format alongside `CF_UNICODETEXT`.

- [ ] **M11** `OnReplaceText` replaces inside `m_wsText` and writes back via
  `SetCellText` (`Grid32Mgr.cpp:3733-3740`) — replacing in a formula cell
  substitutes its result for the formula. Find/Replace also never searches
  `m_wsFormula`.

- [ ] **M12** `OnFillCells` (`Grid32Mgr.cpp:3499-3513`) assigns `m_wsText`
  directly without re-running `InferType`/`FormatCellValue`, so filled numbers
  stay `CT_Text`; it also ignores `m_bFormula`/`m_wsFormula`,
  `m_dwFillDirection` and `m_dwFillRange` entirely.

- [ ] **M13** `OnSortCells` ignores its `m_dwWhich` field and the `wParam`
  argument (`Grid32Mgr.cpp:3524`); `OnFillCells` and `OnFilterCells` ignore
  `wParam` too.

- [ ] **M14** SSF writes floats and doubles with `std::to_wstring`
  (`Grid32Mgr.cpp:3900-3914`), which is fixed at 6 decimal places and uses the
  current locale's decimal separator — precision loss on round-trip and
  breakage under comma-decimal locales.

- [ ] **M15** `CMainFrame::PreTranslateMessage` (`MainFrm.cpp:496-503`) calls
  `CFrameWnd::PreTranslateMessage`, skipping `CFrameWndEx`'s ribbon keyboard
  handling (KeyTips, Alt navigation, ribbon tooltips).

- [ ] **M16** Duplicate command handlers for `ID_CELL_GOTO`: the view
  (`SpreadsheetView.cpp:47`) and the frame (`MainFrm.cpp:42`). MFC routes to the
  view first, so `CMainFrame::OnCellGoto` — the newer implementation — is dead
  code, and the two versions have already diverged.

- [ ] **M17** No `ON_UPDATE_COMMAND_UI` handlers anywhere: Undo/Redo/Paste are
  never greyed out (`OnCanUndo`/`OnCanRedo` exist and are unused), and the
  Bold/Italic/alignment buttons never reflect the current cell's state.

- [ ] **M18** `CGridView::OnTextNotFound` (`GridView.cpp:117`) is empty — a
  failed search gives no feedback at all. `OnEditFind`/`OnEditReplace`
  (`:157-165`) pass empty strings instead of showing a Find dialog.

- [ ] **M19** Documentation drift: `Grid32Mgr.h` says
  `GetCurrentCellFontInfo` "Returns false if no cell exists", but it uses
  `GetCellOrDefault` (`Grid32Mgr.cpp:1216`), which never returns null — it
  always returns `true`.

- [ ] **M20** `GetColumnLabel` (`Grid32Mgr.cpp:90-99`) terminates only via
  `size_t` underflow (`index = index / 26 - 1` wrapping to `SIZE_MAX`) and
  compares that against `maxWidth`. It produces correct labels today, but the
  loop condition is unrelated to the termination condition.

- [ ] **M21** `CSpreadsheetView::PreCreateWindow` ORs `GS_SPREADSHEET` into the
  *view's* window style (`SpreadsheetView.cpp:67`); the grid child's style is
  set independently in `CGridView::OnCreate`. The line has no effect and
  collides with the child-window control-style bit range.

## Performance and scale

- [ ] **P1** Every stream-out format walks the dense `nHeight × nWidth` space
  instead of the sparse `mapCells` (`Grid32Mgr.cpp:3845-3981`) — including the
  SSF path, whose whole point is compactness. At the host's current
  702 × 4096 grid that is 2.9M `GetCell` lookups per save; at any realistic
  spreadsheet size it is unusable. `OnSaveDocument` then repeats the whole pass
  up to 8 times while growing the buffer (`SpreadsheetDoc.cpp:141-154`).

- [ ] **P2** `OnFindText` scans the full dense grid with `GetCellOrDefault`
  (`Grid32Mgr.cpp:3659-3691`) rather than iterating populated cells.

- [ ] **P3** `OnSortCells` (`Grid32Mgr.cpp:3543-3586`) materialises
  `gcs.nWidth` `GRIDCELL` copies **per row** — each with three `std::wstring`s —
  and then writes every column back through `SetCell`. Sorting 100 rows of a
  702-column grid creates ~70,000 cells that did not exist before, permanently
  populating `mapCells` with empties and slowing every later operation.

- [ ] **P4** `RecalculateFormulas` (`Grid32Mgr.cpp:4342-4357`) re-evaluates every
  formula cell from source on every call, and each evaluation re-walks its whole
  dependency chain with no memoisation or topological ordering — O(cells × depth)
  per edit. Needs a dependency graph with dirty marking.

- [ ] **P5** `DrawCells` calls `CreateFontW` **and** `GetDeviceCaps` once per
  visible cell per paint, then `DeleteObject`s the font
  (`Grid32Mgr.cpp:620-638`). Cache `HFONT`s keyed by `FONTINFO`.

- [ ] **P6** `OnPaint` always repaints the entire client rect and ignores
  `ps.rcPaint` (`Grid32Mgr.cpp:224-268`), while every mutator calls
  `Invalidate()` with no rectangle (`:1382`, `:1416`, `:1166`, …). Combined with
  P5, each keystroke repaints and re-creates a font for every visible cell.

- [ ] **P7** `Create` eagerly allocates `COLINFO[nWidth]` and `ROWINFO[nHeight]`
  and fills each with a `std::wstring` label (`Grid32Mgr.cpp:111-162`). Each
  entry carries a `FONTINFO` with its own `std::wstring`. This is the
  structural blocker on an Excel-sized grid — row/column metadata needs to be
  sparse with a shared default.

- [ ] **P8** Dead code from round 1's pattern remains: `RECT r;
  GetCurrentCellRect(r);` computed and unused at `Grid32Mgr.cpp:1380-1381`,
  `:1414-1415` and `:1130-1131` (same shape as the closed L9).

## Enhancements

### Formula engine
- [ ] **E1** Comparison operators (`> < >= <= = <>`), exponentiation `^`, and
  string concatenation `&`.
- [ ] **E2** Real error values (`#DIV/0!`, `#VALUE!`, `#REF!`, `#NAME?`,
  `#CYCLE!`) surfaced as `CT_Error` instead of `0`, `inf` or `nan`. Today
  `=1/0` yields `inf` formatted through `wstringstream`, and an unknown function
  name silently evaluates to `0` (`Formulator.cpp:684-687`).
- [ ] **E3** `COUNTA`, `COUNTIF`, `SUMIF`, `VLOOKUP`/`HLOOKUP`, `INDEX`/`MATCH`,
  `STDEV`, `MEDIAN`, `SUBSTITUTE`, `FIND`, `TEXT`.
- [ ] **E4** Ranges as arguments to *any* function, and multi-argument
  `SUM(A1:A3, B7, 12)` — today `SumRange` takes a single argument.
- [ ] **E5** Absolute references (`$A$1`), named ranges, cross-sheet references.
- [ ] **E6** `AVERAGE` counts blank cells in its denominator
  (`Formulator.cpp:398`); Excel ignores them. `MIN`/`MAX` over an empty range
  return ±infinity (`:230-241`).

### Grid features
- [ ] **E7** Insert / delete rows and columns, with reference fixup. Entirely
  absent — arguably the largest missing feature for a spreadsheet.
- [ ] **E8** Relative-reference adjustment on fill, copy and paste
  (drag `=A1+B1` down → `=A2+B2`), plus fill series (1,2,3…; date sequences).
- [ ] **E9** Multiple sheets. The SSF v2 header already reserves a workbook
  envelope with a sheet count (`Grid32Mgr.cpp:3874-3876`) but only ever writes
  `WB,1` / `Sheet1`.
- [ ] **E10** Freeze panes, hide/show rows and columns, real row filtering
  (see H16), autofit on divider double-click.
- [ ] **E11** A formula bar and name box — currently the only editing surface is
  the in-cell `EDIT` control.
- [ ] **E12** `####` overflow indication for numbers too wide for their column,
  and text spill into adjacent empty cells.
- [ ] **E13** Conditional formatting, data validation, cell comments, charts.

### File formats and host
- [ ] **E14** Genuine `.xlsx` / `.ods` (ZIP container with the required parts),
  and CSV/TSV import & export commands in the ribbon — Grid32 already supports
  the formats, the host only ever asks for `SF_SSF`
  (`SpreadsheetDoc.cpp:126, 147`).
- [ ] **E15** UTF-8 input support on open; today only UTF-16 LE with or without
  a BOM is read (`SpreadsheetDoc.cpp:102-110`).
- [ ] **E16** Printing with pagination, repeating header rows, headers/footers
  and a print area (see H12).
- [ ] **E17** Per-monitor high-DPI awareness, and UI Automation / MSAA exposure
  so the grid is reachable by screen readers.
- [ ] **E18** A `GM_SETBACKGROUND` message (H11), a grid-clear message (H15),
  and a merge-range message (H10) to complete the public API.

### Engineering
- [ ] **E19** `Tests/` is not in `Spreadsheet.sln` (only the two product
  projects are) and covers only the header-only `Grid32Detail` helpers.
  Add the test project to the solution.
- [ ] **E20** Add `CFormulator` tests — B1, B3 and H6 are all pure-logic bugs a
  single test file would have caught. `CGrid32Mgr` needs a message-only host
  window fixture, which `Tests/Grid32Tests.cpp:4-7` already flags as deferred.
- [ ] **E21** No CI. A GitHub Actions workflow on `windows-latest` running
  `msbuild Spreadsheet.sln` plus `Tests/run_tests.bat` would gate all of the
  above.
- [ ] **E22** `Tests/run_tests.bat` probes for "Microsoft Visual Studio\18"
  and the 2022 Community edition only; it should use `vswhere`.
