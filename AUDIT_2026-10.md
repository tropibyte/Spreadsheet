## S — Spreadsheet control and MFC host (new in round 3)

- [x] **S1** (High) Keyboard moves leave the selection behind.
  `IncrementSelectedCell/Page/Edge`, the grid's Tab, and the editor's
  Up/Down/Tab move `m_currentCell` but never collapse `m_selectionRect`. Clear,
  Fill, Sort, Bold, Number format, Align and Format Painter all act on the
  selection, so after Tab from A1 the ribbon edits A1 while showing B1's state.
  GN_SELCHANGE also reports a `range` that does not contain `cellPt`.
- [x] **S2** (High, *verified*) An inline edit commits into whatever cell is
  current at commit time. Clicking another cell (or a scroll arrow) moves
  `m_currentCell` without taking focus from the editor; Enter then writes the
  text into the clicked cell and A1 keeps its old value.
- [x] **S3** (High, *verified*) Formulas read a referenced cell's display text,
  not its value: `CFormulator::GetCellValue` does `std::stod(m_wsText)`.
  Currency "$1,234.50" reads as 0, "25.00%" as 25, a date as its year, TRUE as 0.
- [x] **S4** (High, *verified*) Ribbon Clear only blanks `m_wsText` (it goes
  through `GM_FILLCELLS`/`FILL_TEXT`): formulas survive and come back on the
  next recalc, dependents are not recalculated, a cell is created for every
  empty position, and nothing is undoable.
- [x] **S5** (Medium) Text still in the inline editor is lost on close and on
  save: the edit commits only on `WM_KILLFOCUS`, which happens after
  `SaveModified` has already decided the document is clean.
- [x] **S6** (Medium) Replace All replaces only the first match in each cell
  and counts one; Replace (current) never moves past the cell it just changed.
- [x] **S7** (Medium) Fill Down and Fill Right both copy `sel.start`, and the
  selection is not normalized, so an upward drag fills in reverse.
- [x] **S8** (Medium, *verified*) The Alignment dialog treats `DT_TOP` (0) as
  "unset" and turns Top into Middle; OK also writes all three attributes to the
  whole selection, flattening a mixed selection.
- [x] **S9** (Medium) The persistent (double-click) Format Painter cannot be
  reached: the ribbon's double-click never re-sends the command.
- [x] **S10** (Medium, latent) Select All followed by any formatting command
  creates a GRIDCELL for every position in the grid (≈2.9M on 4096×702), and
  `GetCellOrCreate` falls back to the shared `m_defaultGridCell` when allocation
  fails, so callers then restyle every empty cell.
- [x] **S11** (Low, *verified*) Enter on the grid opens the editor
  (`iswspace(VK_RETURN)`) and commits an untouched cell: an empty cell is
  created, undo is pushed, everything recalculates, the document turns dirty.
- [x] **S12** (Low) Escape sends GN_EDITCANCEL before setting
  `m_bSuppressEditCommit`; a handler that moves focus commits the cancelled
  text, and the flag then swallows the next real commit.
- [x] **S13** (Low) Wrong notification payloads: WM_UNDO/GM_REDO send
  GN_CELLCHANGED for the current cell (and even with an empty stack);
  GM_SETSELECTION sends GN_SELCHANGE when the rect was rejected;
  GM_SETCURRENTCELL reports the stale `range`.
- [x] **S14** (Low) The resized inline editor is the font's em size + 6 px
  tall, which clips descenders (Arial ≥ 72 pt, Segoe UI ≥ 14 pt at 96 DPI).
- [x] **S15** (Low) The Bold tooltip advertises Ctrl+B, but the accelerator
  sends `ID_BUTTON_BOLD`, which nothing handles.
- [x] **S16** (High) Go To (Ctrl+G) never moves: `substr(1, find(L'$') - 1)`
  mangles the reference, rows/columns are built 1-based against 0-based keys,
  only existing cells are reachable, and it returns TRUE on failure.
- [x] **S17** (Medium) Undoing WM_CLEAR restores nothing: the Delete op never
  sets `row`/`col` (uninitialized), and `RestoreCells` ignores `oldCells` for
  Delete, then writes a default cell at that undefined position.

## G — PhotoGalleryGrid (new control, first review)

- [x] **G1** (High) `AfterPaint` caches `bAuto = m_loader && PGGS_AUTOLOAD`;
  a GETDISPINFO handler that clears PGGS_AUTOLOAD stops the loader, and
  `m_loader->SetWanted` then dereferences null.
- [x] **G2** (Medium) If a handler deletes items during a click,
  `CancelPress()` clears the press and `OnLButtonUp` returns without
  `ReleaseCapture`: the gallery keeps the mouse captured.
- [x] **G3** (Medium) A result with a stale epoch is dropped without
  `InvalidateKey`, and the re-request was refused while the old job was in
  flight, so the tile stays a placeholder until an unrelated repaint.
- [x] **G4** (Medium) Shift+click / Shift+arrow with no anchor never set
  `m_iAnchor`, so Shift cannot extend until a plain click sets one.
- [x] **G5** (Low) `Trim` treats "drawn this frame" as "on screen"; partial
  paints let it sweep visible loading/failed entries (re-decoding broken files,
  re-firing PGGN_THUMBFAILED, resetting OneDrive retries).
- [x] **G6** (Low) `OnInsertItem` shifts focus and anchor but not
  `m_press.iItem`; a drag then names the wrong photo.
- [x] **G7** (Low) `m_pathBuf` is one shared buffer handed to the host and read
  back after the notification; a nested request overwrites it.
- [x] **G8** (Low) A vetoed implicit "let go" (deselect the previous item in
  single-select, unfocus the old focus) is treated as success, so two items end
  up selected or focus moves without notification.
- [x] **G9** (Low) `OnSetTileMetrics` starts from the zoomed `m_metrics` and
  stores it as the Ctrl+0 baseline.
- [x] **G10** (Low) The wrapper's convenience `InsertItem` always sets
  PGGIF_THUMB, so a NULL bitmap resets an already-loaded cache entry.
- [x] **G11** (Low) Owner-data items without PGGIF_KEY get index-based keys
  that `OnSetItemCount` never invalidates; shifted items show stale pictures.
- [x] **G12** (Low) `ContentHeight`/`RowTop` are `int`; a one-column feed of
  ~1.1M large tiles overflows and the gallery stops scrolling.
- [x] **G13** (Low) PGGIF_TEXT is documented as the tooltip / accessible name
  but nothing shows it; PGGS_SHOWSELALWAYS's comment does not match what it does.
- [x] **G14** (Low) `WM_GETDLGCODE` does not claim Enter, so in a dialog Enter
  presses the default button instead of sending PGGN_ITEMACTIVATE.

## Behaviour and API changes made by the fixes

Hosts and users will notice these.

**Keyboard and mouse**
- Shift+arrow, Shift+Page Up/Down, Shift+Home and Shift+click extend the
  selection from the active cell; Ctrl+Shift+arrow extends to the edge. Shift+arrow
  used to move a page at a time (Page Up/Down still do).
- Typing over a cell replaces its content, as in Excel; F2 or a double-click
  edits the existing content. Backspace opens an empty editor (Enter then
  clears the cell, Escape keeps it). Enter on the grid does nothing but send
  NM_RETURN. Delete clears the whole selection.
- Home, Ctrl+Home and Ctrl+End move as in Excel; the mouse wheel scrolls.
- The scroll bars scroll the view; their arrows used to move the active cell.
- A right-click outside the selection moves the active cell there first.
- New accelerators: Ctrl+I, Ctrl+U (font), Ctrl+Y (redo), Ctrl+F, Ctrl+H
  (find, replace). Ctrl+B now reaches Bold. While a cell is being edited,
  Ctrl+C/X/V/Z/A act on the editor's text.
- Format Painter: double-click keeps it armed until clicked again.
- Find Next wraps around the sheet once.

**Public API (`grid32.h`)**
- Cell coordinates travel by pointer: `GM_SETCELL`, `GM_SETCELLTEXT` and
  `GM_GETCELLTEXT` take a `const GRIDPOINT*` in wParam; `GM_SETCURRENTCELL`
  (coordinate form) and `GM_GETCURRENTCELL` take one in lParam.
- No C++ library types: `FONTINFO::m_szFontFace` is a `WCHAR[LF_FACESIZE]`
  (it was `std::wstring m_wsFontFace`); the find, replace and filter structs
  take `LPCWSTR` (`m_pwszFindText`, `m_pwszReplaceText`, `m_pwszFilterText`);
  `GM_SETCELL` and `GCFILLSTRUCT` describe a cell with the new `GCCELLINFO`;
  `GM_ENUMCELLS` returns the positions of the populated cells. `GRIDCELL`,
  `cell_base` and `CellType` are internal (`grid32_cell.h`); `ROWINFO` and
  `COLINFO` are gone.
- New messages: `GM_COMMITEDIT`, `GM_SETBACKGROUND`, `GM_GETBACKGROUND`,
  `GM_MERGECELLS`, `GM_GETMERGE`, `GM_GETUSEDRANGE`, `GM_RENDERRANGE`,
  `GM_REPLACEALL`, `GM_CLEARALL`; `WM_PRINTCLIENT` is handled.
- `GM_SETCHARFORMAT` takes `SCF_MASKED` with a `GCCELLCHARFORMAT::m_dwMask`
  (`GCFM_*`) to apply single attributes.
- `GCFILLSTRUCT` has `m_range` for `FILLBYRANGE`, and `m_dwFillDirection` now
  fills each column or row from its own edge cell. `GCSORTSTRUCT::m_dwWhich`
  names the key column (`GCS_KEYCOLUMN`), and `GM_SORTCELLS` takes `GCSF_*`
  flags in wParam. `GM_FILTERCELLS` hides rows (`FILTER_NONE` shows them,
  `FILTER_MATCHCASE` is a flag). Reserved wParams must be 0.
- Messages return their real result: the `GM_SET*` setters, `GM_STREAMIN` and
  `GM_STREAMOUT` return TRUE on success, `GM_ENUMCELLS` its count, `WM_UNDO`
  and `GM_REDO` whether anything was undone. `GM_GETSELECTION` returns the
  normalized selection; `GM_SETSELECTION` clamps the far corner and rejects a
  selection that starts off the grid. `GM_GETROWHEIGHT` is 0 for a filtered row.
- An empty cell's `GM_GETCELLTEXT` is a success with an empty string.

**Files**
- SSF writes every existing cell, including cells that hold only formatting
  (a highlighted empty cell, a merged block's anchor), which it used to skip,
  and a `DF` record for whole-sheet formatting. Older readers reject the `DF`
  record; files without it read as before.
